# 章节编辑技能

## 核心职责

对已有章节正文执行三类编辑操作：

1. **文笔优化** — 提升文字表现力（Show Not Tell、感官细节、句式丰富化），不改变情节和角色行为
2. **反馈修订** — 基于读者反馈精准修复具体问题（节奏/衔接/角色行为不合理等），最小修改原则
3. **内容修改** — 按用户指令修改段落内容（重写战斗/追加描写/调整对话等），可涉及大段重写

## 上下文契约

编排层在调用前按以下清单加载上下文：

| 槽位 | 内容 | 加载方式 |
|------|------|---------|
| 章节正文 | `chapters/第{N}章.txt` 全文 | read |
| 修改指令 | 用户原始修改请求 | 编排层从用户输入提取，直接填入模板 |
| 编辑模式 | 自动判断：文笔优化 / 反馈修订 / 内容修改 | 编排层根据用户输入匹配 |
| 本章分纲 | `outline/分纲/卷{卷号}/第{N}章.yaml` 关键字段 | read（场景、出场角色、冲突、转折） |
| 出场角色档案 | 出场角色完整档案 | project_index.yaml → read |
| 前章衔接 | 第{N-1}章最后 100 字 | `last_100.py` |
| 活跃风格 | config.yaml `活跃风格` → 风格文件 | read 全文件（≤30行） |

## 三种模式的区分

### 文笔优化

触发词：润色、优化、文笔、措辞、表达

- 保持原意、情节、角色设定完全不变
- 用 Show Not Tell 原则替换抽象描述
- 丰富感官细节、优化句式节奏
- 参考：`references/enhancement_tips.md`

### 反馈修订

触发词：反馈、读者说、有人提了、评论

- 精准修正，只修改反馈指出的具体问题
- 从反馈理解"不适点"的文本根因
- 保留原素材，在原文基础上插入/改写最小必要内容
- 修改后重新确认与前章的衔接和悬念钩子

### 内容修改

触发词：改一下、调整、把...改成、重写、追加、删除

- 精确执行修改指令，不波及无关段落
- 若指令模糊（"写得更激烈一点"），可针对具体段落给出修改方案让用户确认
- 修改后验证角色一致性和情节逻辑

## 输出

- 编辑后的 `chapters/第{N}章.txt`（edit 写入）
- 不修改 `chapters/.metas/` 元数据文件，不涉及 auto_update

## 参考

- `references/enhancement_tips.md` — 文笔提升技巧（Show Not Tell、感官细节、句式变化）
- `references/checklist_example.md` — 情节点覆盖检查示例

## HARD CONSTRAINTS

1. 不改变未涉及段落的内容
2. 修改后角色行为必须符合角色档案设定
3. 修改后验证与前章的衔接
4. 反馈修订时最小修改，不推倒重写
5. 内容修改时若指令模糊，先确认再执行
