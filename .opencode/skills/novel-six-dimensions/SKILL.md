# 六维冲突设计方法论（Six Dimensions Design Framework）

## 定位

本技能是一套**横切创作方法论**——不绑定单一的焦点类型（scene/character_arc 等），而是作为跨领域的冲突设计参考。

**使用条件**：当创作任务涉及角色深层次动机设计、情节冲突设计、人物关系张力设计时，由规划主 agent（设计选维）自主决定加载本技能。

### 何时加载（由 novel-planner 注入）

| 场景 | 加载方式 |
|:----|:---------|
| 创建/编辑角色（character_arc）且角色需要深层动机 | ✅ planner 注入——至少选 1 个维度作为核心驱动 |
| 设计情节冲突（plot_thread） | ✅ planner 注入——用于判定冲突的维度归属 |
| 设计总纲/卷纲/章纲（structure） | 🔶 可选——当需要为整卷设计统一的情感冲突轴时 |
| 创意发散/方案生成（ideation） | ✅ planner 注入——用维度约束框定创意的方向 |
| 纯技术性操作（导出/质检/查重） | ❌ 不加载 |

> **加载者**：横切技能（cross-cutting）。planner 注入设计选维、writer 注入冲突深度、ideation 注入约束框定方向——均通过 `load_skills=["novel-six-dimensions"]` 加载。

## 框架总览

六个维度，三层结构：

```
表层（看得见的冲突）
  ① 个体竞技层  — 天赋 vs 努力 / 选择 vs 坚持
  ② 社会结构层  — 资源 vs 关系 / 奋斗 vs 管道
  ③ 系统规则层  — 规则 vs 创新 / 合规 vs 突破

底层（看不见的驱动力）
  ④ 时间消磨层  — 初心 vs 惯性 / 清醒 vs 麻木
  ⑤ 组织异化层  — 不可替代 vs 可替换 / 身份 vs 螺丝钉
  ⑥ 心智代际层  — 出身烙印 vs 后天重塑 / 匮乏 vs 配得感
```

每个维度由四个字段构成：

| 字段 | 功能 | 创作用途 |
|:----|:-----|:---------|
| **事实** | 该维度下的现实规则 | 世界观底层设定——角色无法改变的那部分 |
| **不处理的后果** | 看懂了但不去处理会怎样 | **剧情终点预告**——角色最怕的局面 |
| **回响** | 一句洞见性总结 | 角色的核心主题句 |
| **处理方式** | 理论上的应对策略 | 角色理论上的出路——但他不一定做得到 |

> 完整六维数据见 `references/framework.md`

## 设计原则体系（四模式 + 三原则）

### 四种冲突设计模式

详细展开见 `references/design_principles.md`，摘要如下：

| 模式 | 描述 | 适用场景 |
|:----|:-----|:---------|
| **A · 单维聚焦** | 一个角色只打一场核心维度的仗 | 配角、功能性角色、单卷故事 |
| **B · 多维叠加** | 表层一个维度，底层另一个维度 | 主角、长篇主线角色 |
| **C · 维度对立** | 两个角色的冲突来自不同维度 | 对手戏、派系斗争、观念之争 |
| **D · 维度跃迁** | 角色在一部作品中分段换战场 | 长篇成长弧线、多卷史诗 |

### 三条硬设计原则

1. **张力原则**：冲突发生在"知道处理方式但做不到"的空间里
2. **终点预告原则**："不处理的后果"就是剧本的终点——反派的攻击目标、剧情的顶点
3. **三维上限原则**：同一角色不同时激活超过 3 个维度

## 工作流集成

### 与现有流程的对接点

```
grill（需求发现）
  │
  ├─ 识别用户意图是否涉及深层冲突设计
  │     │
  │     └─ 是 → 加载本技能 → 用选维清单引导追问
  │
  ▼
ideation（方案生成）
  │
  ├─ 用维度约束框定创意的边界
  ├─ 用维度对立（模式C）生成冲突方案
  │
  ▼
novel-writer（创作执行）
  │
  ├─ 将选定的维度嵌入角色 content 的「角色弧线」字段
  ├─ 将不处理的后果映射为关键事件
  ├─ 将处理方式映射为角色行为逻辑（做得到或做不到）
  │
  ▼
graph（持久化）
     └─ 维度选择记录在角色的 tags 或 content 中
```

### 提示词注入点

由 novel-planner 在调度子 Agent 前注入：

```markdown
### 六维冲突设计参考
已加载 novel-six-dimensions 技能。
当前角色的核心冲突维度建议：[维度名称]
对应「不处理的后果」：...
对应「事实」（角色无法改变的部分）：...
```

不注入完整六维数据——只注入**当前相关**的维度内容。

## 模式 C 产出后的关系落盘（桥接到 graph）

使用**模式 C（维度对立）**确认对立关系后，由执行者（novel-writer/ideation）用 novel-tool 把对立结构落盘到 graph，供后续写作与 R2 一致性检查引用：

- 对立双方为角色 → `graph.add_relation(source="{角色A}", target="{角色B}", rel_type="relates_to", label="维度对立", bidirectional=true)`
- 冲突已实体化为具体事件/设定 → 追加 `rel_type="contradicts"` 边
- 派系层面（对立升级为阵营冲突）→ `member_of` / `controls` 边

> 关系类型选用与开放标签规则见 `novel-v2-core/references/relation_guide.md`。

## 快速设计流程

```
Step 1: 从 6 个维度中选 1~2 个作为角色的核心冲突轴
        ↓
Step 2: 读该维度的「事实」——这是角色无法改变的世界规则
        ↓
Step 3: 读「不处理的后果」——这就是角色最怕的终点
        ↓
Step 4: 读「处理方式」——角色理论上可以怎么走
        ↓
Step 5: 设计阻碍——让角色知道处理方式，但做不到
        ↓
Step 6: 可选——叠加第 2 个维度（注意三维上限原则）
```

## 核心约束

1. **不替代已有技能**——本技能是方法论参考，不操作 graph，不生成内容
2. **按需加载**——不要在任何创作中都注入六维，只有在涉及深层冲突设计时才使用
3. **选维不超过 3 个**——三维上限原则是硬约束
4. **注入最小化**——只注入当前相关的维度内容，不投喂完整框架
