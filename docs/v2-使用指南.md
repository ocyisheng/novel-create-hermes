# V2 使用指南

## 概述

V2 是 novel-create-hermes 的下一代架构，基于**叙事单元网络**替代现有的离散 YAML 文件体系。本文档说明如何在日常创作中使用 V2。

---

## 一、快速开始：迁移现有项目

### 1.1 查看可迁移的项目

```bash
python .opencode/shared/v2/migrate.py --list-projects --novels-root novels
```

输出示例：
```
发现 4 个项目:
  novels/大宋女仵作
  novels/测试仙途
  novels/空山闻仙
  novels/穿越三国成刘谌
```

### 1.2 执行迁移

```bash
# 先 dry-run 看看会导入什么（不实际写入）
python .opencode/shared/v2/migrate.py --project-root novels/空山闻仙 --dry-run

# 正式迁移 + 验证 + 生成报告
python .opencode/shared/v2/migrate.py --project-root novels/空山闻仙 --verify --report
```

迁移过程：
```
📁 扫描项目文件...        → 自动发现所有 YAML/TXT 文件
📥 导入文件到 graph...    → 按类型映射到叙事单元
🔗 建立关系...            → 从分纲的出场角色/关联情节线字段推断关系
📸 创建迁移快照...        → 可回滚到此状态
✅ 验证迁移完整性...      → 覆盖率/关系数/事件溯源检查
📄 生成迁移报告...        → graph/migration_report.md
```

迁移后项目目录新增：
```
novels/空山闻仙/
├── graph/                  # ← 新增：graph 存储
│   ├── nodes.jsonl         #     叙事单元数据
│   ├── edges.jsonl         #     关系数据
│   ├── events.olog         #     事件溯源日志
│   ├── snapshots/          #     快照
│   └── migration_report.md #     迁移报告
├── characters/             # 原有文件不变（DUAL_WRITE 兼容）
├── worldbuilding/          # 原有文件不变
└── ...
```

## 二、Python API 用法

### 2.1 基础：叙事单元 CRUD

```python
import sys
sys.path.insert(0, ".opencode/shared/v2")

from graph_schema import UnitType, UnitStatus, RelationType
from graph_store import GraphStore

# 打开项目（自动创建 graph/ 目录）
store = GraphStore("novels/空山闻仙")
store.initialize()

# ── 创建 ──
scene = store.create_unit(
    type=UnitType.SCENE,
    unit_name="后山夜谈",
    content="苏长老在后山找到林昭，师徒二人月下对话。",
    tags=["关键对话", "师徒"],
    belongs_to_chapter=5,
    actor="user",
)

# ── 创建关联的角色和情节线 ──
char = store.create_unit(
    UnitType.CHARACTER_ARC,
    "林昭",
    '{"trait": "隐忍", "goal": "复仇"}',
    tags=["主角"],
)

plot = store.create_unit(
    UnitType.PLOT_THREAD,
    "主线-复仇",
    "林昭的复仇之路",
)

# ── 建立关系 ──
store.add_relation(char.id, scene.id, RelationType.PARTICIPATES_IN)
store.add_relation(scene.id, plot.id, RelationType.IMPLEMENTS)

# ── 查询 ──
# 按名称查找
found = store.get_unit_by_name("林昭")

# 按类型过滤
all_scenes = store.find_units(type=UnitType.SCENE)

# 邻居查询（1度关系）
neighbors = store.get_neighbors(scene.id, max_depth=1)
print(neighbors[1])  # 直接关联的单元ID集合

# 路径查找
path = store.find_path(char.id, plot.id)
print(path)  # ['ca_xxx', 'sc_xxx', 'pt_xxx']

# ── 更新 ──
store.update_unit(
    scene.id,
    confidence=0.9,           # 确信度提升
    tags=["关键对话", "师徒", "伏笔"],
    actor="user",
)

# ── 归档（软删除）──
store.archive_unit(scene.id)

# ── 快照 ──
snapshot = store.create_snapshot({"reason": "写完第5章后的备份"})

# 列出快照
for s in store.get_snapshots():
    print(f"  {s['id']}: {s['timestamp']} ({s['unit_count']} units)")

# 恢复到快照
store.restore_snapshot(snapshot.snapshot_id)

# ── 持久化 ──
store.flush()
```

### 2.2 创作会话管理

```python
from session import SessionManager, CycleType, SessionPhase

# 初始化会话管理器
mgr = SessionManager("novels/空山闻仙")

# 在会话中切换焦点（写着写着突然想加个角色）
```

## 三、与现有创作流程的集成

### 3.1 双写模式（DUAL_WRITE）

启用后，现有的 SKILL.md 写入文件时，同时写入 graph。文件系统是兼容层，graph 是真相源。

```python
from adapter import LegacyFileAdapter, AdapterMode
from graph_store import GraphStore
from projection_engine import ProjectionEngine

store = GraphStore("novels/空山闻仙")
store.initialize()
proj = ProjectionEngine(store, "novels/空山闻仙")
adapter = LegacyFileAdapter(store, proj, mode=AdapterMode.DUAL_WRITE)

# 写角色 YAML → 同时写入 graph + 文件
adapter.write_yaml(
    "novels/空山闻仙/characters/新角色.yaml",
    {"索引信息": {"名称": "新角色"}, "摘要": {"核心特质": ["勇敢"]}},
)

# 写章节正文 → 同时创建 CHUNK 单元 + TXT 文件
adapter.write_chapter(
    "novels/空山闻仙/chapters/第6章.txt",
    "正文内容...",
    chapter_number=6,
)
```

## 五、完整示例：一次创作会话

```python
import sys
sys.path.insert(0, ".opencode/shared/v2")

from graph_schema import UnitType, RelationType
from graph_store import GraphStore
from session import SessionManager, CycleType
from workspace import WorkspaceBuilder

# 1. 打开项目
store = GraphStore("novels/空山闻仙")
store.initialize()

# 2. 启动会话
mgr = SessionManager("novels/空山闻仙")
session = mgr.start_session(
    focus_type=UnitType.SCENE,
    focus_unit_id="sc_001",
    cycle_type=CycleType.EXPANSION,
)

# 3. 构建工作空间
builder = WorkspaceBuilder(store)
ws = builder.build("sc_001", preheat_level="warm")
prompt = ws.to_prompt_block("warm")

# 4. 创作（模拟子 Agent 返回）
agent_response = """林昭站在后山练剑坪上。
QUERY: character_background(name="林昭")
师父站在三步之外。"""

# 5. 处理 QUERY
from orchestrator import V2Orchestrator
orch = V2Orchestrator("novels/空山闻仙")
clean, query_records = orch.process_subagent_response(agent_response)

# 6. 保存到 graph
chunk = store.create_unit(
    UnitType.CHUNK, "第5章片段", clean,
    belongs_to_chapter=5,
    actor="novel-crafter",
)

# 7. 结束会话
mgr.end_session()
store.flush()
mgr.save_user_state()

# 8. 查看统计
print(store.stats())
print(query_records)
```

## 六、架构转换对照

| 概念 | 现有架构 | V2 架构 |
|------|---------|---------|
| 数据模型 | 三层 YAML（_meta + 索引信息 + 摘要 + 完整档案） | 叙事单元网络（NarrativeUnit + Relation） |
| 存储格式 | 离散 YAML/TXT 文件 | JSON Lines (graph/) + 投影 (projections/) |
| 一致性 | 手动索引重建 (rebuild_project_index.py) | 自动保证（graph 是唯一真相源） |
| 上下文加载 | chapter_context.py 全量推送 | WorkspaceBuilder 按焦点+级别按需加载 |
| 写作流程 | P1-P15 线性状态机 | 创作会话嵌套循环 (assess→execute→review→settle) |
| 信息获取 | 编排层决定你需要什么 | 子 Agent 通过 QUERY 协议自主请求 |
| 回滚 | .bak 文件还原 | 事件溯源 + 快照 |
| 创作灵感 | 无捕获机制 | NOTE 类型 + 意图列表 |
