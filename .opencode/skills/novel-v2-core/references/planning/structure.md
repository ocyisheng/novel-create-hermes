# structure — 整体结构与美学组织（OUTLINE / ARC_PLAN / VOLUME_PLAN / CHAPTER_PLAN）

## 定位

整体结构设计的方法论文档，覆盖从总纲（OUTLINE）到部篇大纲（ARC_PLAN）、卷大纲（VOLUME_PLAN）、章纲（CHAPTER_PLAN）四个层级。按焦点类型的 SUBTYPE 区分具体方法论。

## 何时加载

- FOCUS TYPE=outline 或 arc_plan 或 volume_plan 或 chapter_plan 时自动加载
- 根据 SUBTYPE（总纲/部大纲/篇大纲/卷大纲/章纲）选择对应的方法论章节

## 结构由脚本保障

content JSON 的字段结构由 `type_registry.py`（TypeRegistry）自动校验。各类型的子类型字段不同（详见 type_registry 子类型配置）：
- OUTLINE → `模式选择`（沙漏/长链/螺旋/环状/多线交织）
- ARC_PLAN → `命名规范`（部/篇）
- VOLUME_PLAN → 无子类型字段（卷号本身就是分类）
- CHAPTER_PLAN → `本章功能`（开篇/推进/冲突/转折/展示/过渡/收束）

## 创作方法论（需 LLM 判断）

> 以下为通用方法，适用所有结构层级（总纲、部大纲、篇大纲、卷大纲、章纲）。本书级方法在此定义，各子类型在此基础上增加专属增量。

### 七面观照检视清单

> 🔍 设计自检 — 结构设计阶段逐一过，不是一次性功课

| 面向 | 自问 |
|------|------|
| 故事 | 读者最关心"然后呢"的点是什么？ |
| 人物 | 谁是圆形谁是扁平？为什么？ |
| 情节 | 核心谜团是什么？因果关系如何组织？ |
| 幻想 | 需要读者付额外代价吗？值不值？ |
| 预言 | 人物有"向后延展超越自身"的潜力吗？ |
| 模式 | 整本书的美学形状是什么？（沙漏/长链/螺旋/环状） |
| 节奏 | "重复加变化"的动机是什么？在哪里变奏？ |

七面观照不是一次性功课——在总纲阶段定型，在卷大纲阶段检验，在章纲阶段落实到场景序列。

### 模式与节奏的选择

| 选择 | 优势 | 代价 | 适用场景 |
|------|------|------|---------|
| 模式优先 | 清晰对称的美感 | 人物类型受限，生活被过滤 | 艺术完整性的精致小说（亨利·詹姆斯式） |
| 节奏优先 | 不牺牲人物，内在凝聚 | 不易达成整体效果 | 规模宏大、人物众多的小说（普鲁斯特式） |

铁律：坚持"扩展"而非"完成"，"开放"而非"自足"。

### 本体论

小说本体不是传递思想或反映现实，而是"一个词在时间中的奇遇"。

- 卡尔维诺《马可瓦多》中的"风"——少数敏感的人才察觉得到，却带来一整个世界。
- 你的小说从一个什么"词"开始？这个词展开后能构筑一整个世界吗？

> 自问：我能用一句话说出"这个故事是关于什么的"吗？
> - 能 → 可能太浅了（或者你是寓言作家）
> - 不能 → 可能正在对的方向上
> - 如果总纲能用一句话概括"我想表达的是……"，那小说是多余的。

### 跨越式参照

> 💡 激发思维 — 通过跨越式参照打破你自己的惯性

把不同时代的小说家放在同一房间里各自写你的设定。金庸会怎么写？曹雪芹会怎么写？刘慈欣会怎么写？J.K.罗琳会怎么写？

目的不是抄袭，是通过跨越式参照发现你自己的路径。如果所有人写出来都一样——你的设定太安全了。

### 不必过度构建

> ⚠️ 收缩原则 — 检查结构膨胀的信号

"有序而不乱之时即小说死亡之日。"当结构变得过于精密，警惕"伪学术"陷阱：不是分类越细就越好。
- 设定的价值不在于数量，在于必要性

> 自问：这条情节线删掉，小说的核心体验会受损吗？如果不会——删掉它。

### 开放式结构

开放式百科全书——小说不必拘泥于圆满结局、写实规范或结构统一。

当陷入"必须兜回来"的焦虑时，自问：这条线一定要收吗？让它悬着是不是更好的选择？

### 场景串联

没有固定的模式分类——重要的是你理解场景和场景之间的叙事关系。因果递进、交替呈现、压力累加、起承转合，这些是常见的组织方式，但不构成封闭集合。检验：如果交换任意两个场景的顺序，读者的感受会不同吗？不会→这两个场景之间的叙事关系不够紧密。

## 按子类型的方法论选型

结构设计的 5 个子类型形成一条从宏到微的链路。以下按 `SUBTYPE` 参数展开专属增量——通用方法已在上方覆盖，此处只写该子类型独有。

### 总纲

总纲适用全部通用方法。总纲阶段的专属增量：

#### 本体论在总纲中的应用

- 七面观照中的 **模式** 一项在总纲阶段定型。检验：选定的形状（沙漏/长链/螺旋/环状/多线交织）是否贯穿全书？在中途如果有偏离，是否有结构理由？
- **本体论核心** 字段用于总纲——不是交代情节，是交代"这部小说作为一个独特世界的精神内核是什么"。检验：这个内核从第 1 章到最终章，始终在场吗？还是只存在于总纲文档中？
- 总纲决定了**全书的美学承诺**——读者在早期建立的预期不需要一一兑现，但需要一一回应。检验：全书读完最后一章，回头对照总纲——哪些被实现了、哪些被刻意绕过了、哪些变形了？变形本身也可以是承诺的兑现方式。

### 部大纲 / 篇大纲

部/篇是可选层级，适用于千章级项目。200 章以内的项目卷→章就足够了。

```
部/篇（人界篇）→ 卷（黄枫谷卷）→ 章（第15章）→ 场景（练剑场告别）
```

在 `config.yaml` 中启用：
```yaml
叙事层级:
  部: true
  卷: true
  章: true    # 始终启用
```

启用后 `NarrativeUnit.structure_path` 自动扩展到四层，投影引擎调整路径模板。

> 部/篇的意义在于让你在千章级别讨论"人界篇的节奏偏慢、灵界篇的冲突更密集"这类宏观问题。

**部/篇弧线**：跨越多个卷的大叙事弧。核心问题——
- 部的核心主题是什么？几卷完成？
- 部的起点到终点是什么变化？
- 同一部中的卷序应形成一条宏观情绪曲线——连续多卷保持同一节奏密度会让读者疲劳或弃书

**层级间过渡**：

| 层级 | 过渡类型 | 示例 |
|------|---------|------|
| 部/篇间 | 大时间跳跃/地域转换/新阶段开始 | 人界篇→灵界篇（飞升） |
| 卷间 | 时间跳跃/视角转移/场景切换 | 黄枫谷卷→乱星海卷（出海） |
| 章间 | 因果连接/情绪延续/悬念过渡 | 第15章→第16章（"剑已出鞘"） |

过渡原则：层级越高，信号需要越清晰。部/篇间过渡需要明确的标志事件（飞升、破界、转世），章间过渡只需一句话或一个空行的余韵。

### 卷大纲

一卷是一个相对独立的叙事单元——有自己的人物弧线片段、情节起承转合、情感节奏。

| 要素 | 说明 |
|------|------|
| 卷核心冲突 | 本卷要解决的主要矛盾，不一定是全书的最终冲突 |
| 起始状态 | 本卷开始时角色/世界的状态 |
| 终点状态 | 本卷结束时发生了什么改变 |
| 情绪基调 | 本卷的总体情绪（紧张/舒缓/悲壮/轻松） |

**卷内节奏类型**（同一卷可以混合多种）：

| 节奏型 | 冲突密度 | 适用 |
|-------|---------|------|
| 推进 | 高/递进 | 主线推进、副本攻略 |
| 过渡 | 低/缓冲 | 角色交流、世界观展示 |
| 高潮 | 极高/多线汇聚 | 决战、反转、揭秘 |
| 收束 | 中/沉淀 | 情绪沉淀、伏笔回收 |

### 章纲

章纲是章节的**节奏和结构设计**——规划场景之间的连接关系、情绪走向、信息释放节奏，而不是替每个 SCENE 写 content。

**章纲 vs SCENE 的职责边界**：章纲回答"这一章怎么推进"，SCENE 回答"这一场发生了什么"。章纲里不需要写每个场域的 POV 和地点——那是 SCENE 的事。

#### 场景序列设计

决定场景顺序时思考的问题：

- 情绪弧线：这一章的情绪起点和终点是什么？中间经历了几个转折？
- 信息分布：关键信息在哪个场景释放？太早读者猜到底，太晚读者失去耐心。
- 节奏交替：紧张场景后需要舒缓场景缓冲吗？还是这一章就是要一气呵成？
- 视角分配：换视角时读者需要多少信号才能跟上来？

#### content 字段

章纲 content 的字段及含义（可调用 `graph.schema_info` 查看）：
- `本章功能` — 本章在全书的叙事定位（开篇/推进/冲突/转折/展示/过渡/收束）
- `场景序列` — 有序的场景规划列表
- `情绪弧线` — 本章情绪起伏（可选）
- `信息释放计划` — 本章释放给读者的信息片段（可选）
- `备注` — 留给自己的提醒（可选）
- **注意**：章纲没有 `子类型` 字段。`结构模式` 属于 `总纲（OUTLINE）` 的 `模式选择` 字段。

**以下信息属于 SCENE 或方法论领域，不得写入章纲**：具体的感官描写、角色的细微动作、对话内容、章节的情绪弧线、场景的节奏设计——这些由 `scene.md` §创作方法论指导 LLM 在写作时自行把握。场景的计划数量与顺序由 PLANS 边承载（章纲的规划意图），实际执行的场景由 CHUNK 的 BELONGS_TO 边承载。

> **规划与执行解耦**：章纲通过 PLANS 边声明计划包含的场景（规划层）；正文（CHUNK）通过 BELONGS_TO 边关联实际执行的场景（执行层）。两套边独立——增减场景只操作 BELONGS_TO，章纲的 PLANS 边保持规划原样。比对 PLANS 与 BELONGS_TO 的差集可生成"计划 vs 执行"偏差报告。

**出场角色**：章纲中列出哪些角色参与本章。每个场域的具体出场角色在 SCENE 中指定。新角色引入需有自然的切入点。

## 参考数据

> 📏 以下为字数规划参考值，是诊断工具而非镣铐。不同项目体量差异极大，应根据实际预期缩放。

### 层级化叙事尺度

小说叙事单元按粒度分为四个层级：

| 层级 | 叙事功能 | 最小有效篇幅 | 典型范围 |
|------|---------|------------|---------|
| 节拍 | 一个冲突的起（发现→尝试→阻碍） | 2000-4000字 | 1章 |
| 场景 | 一个冲突的承转合（交锋→转折→结果） | 3000-6000字 | 1-2章 |
| 剧情弧 | 一个完整副本/秘境/大事件 | 1-5万字 | 5-25章 |
| 卷/部 | 一个明确叙事目标的达成 | 5-30万字 | 15-150章 |

### 卷节奏密度系数

| 节奏型 | 建议场景字数比 | 说明 |
|-------|--------------|------|
| 推进 | 场景×1.0 | 基准 |
| 过渡 | 场景×0.7 | 缓冲 |
| 高潮 | 场景×1.3 | 密集 |
| 收束 | 场景×0.8 | 沉淀 |

> 以上系数表达的是**卷级比例**。单个场景的具体字数范围见 `scene.md` §叙事密度指引。

### 章纲字数带

| 类型 | 字数 | 场景数 |
|------|------|-------|
| 快速章 | 2000-3000字 | ≤2 |
| 标准章 | 3000-5000字 | 2-3 |
| 长章 | 5000-8000字 | 3-5 |

章纲控制的是章节总字数和场景间的比例关系。章纲的场域序列里用比例指示（"第一场短一些、第三场是重头戏"），每个场景内部的具体字数交给 SCENE 层。

### 字数偏差诊断

引擎在工作空间加载时自动检查：CHUNK 是否关联了 SCENE（通过 BELONGS_TO 边），以及 CHUNK 在该章是否有角色或情节线上下文。写作时对照 `scene.md` 的密度预算表控制节奏。
