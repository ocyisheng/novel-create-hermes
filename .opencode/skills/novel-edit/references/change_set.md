## 输出格式

你的输出是一个 JSON 格式的变更集（Change Set），描述对当前实体的精确修改。
**不要输出完整的 YAML 文件，只输出变更集。**

### 变更集格式

```json
{
  "changes": [
    {
      "op": "replace",
      "path": "字段的点号分隔路径",
      "old_value": "修改前的值",
      "new_value": "修改后的值"
    }
  ],
  "summary": "人类可读的变更摘要（不超过 200 字）",
  "related_impacts": ["需要用户确认的联动影响提示"]
}
```

### 操作类型

| 操作 | 适用场景 | 必须参数 |
|------|---------|---------|
| `replace` | 替换已有字段的值 | `path`, `old_value`, `new_value` |
| `add` | 新增之前不存在的字段 | `path`, `value` |
| `remove` | 删除字段或列表项 | `path` |
| `add_to_list` | 向列表追加/插入元素 | `path`, `value`, `position`（可选，默认末尾） |
| `remove_from_list` | 从列表删除指定索引元素 | `path`, `index` |

### path 格式说明

- 使用点号 `.` 分隔嵌套层级。例如：`完整档案.性格.核心特质`
- 列表索引使用数字作为最后一级。例如：`完整档案.性格.优点.0` 表示优点列表的第一个元素
- path 必须对应 YAML 中真实存在的字段路径（`add` 操作除外）

### 约束

1. **只修改 changes 中列出的字段。其他字段一律不变。**
2. 每个 path 必须是 YAML 中存在的有效嵌套路径（`add` 操作的父级路径必须存在）。
3. `replace` 操作必须提供 `old_value`，用于冲突检测。
4. `summary` 必须清晰描述每个修改的 before/after。
5. 如果修改有联动影响（如改性格可能影响目标），在 `related_impacts` 中列出。
6. 输出必须是一个有效的 JSON 对象。

### 示例

**用户请求**：把主角的性格从"隐忍谨慎"改为"杀伐果断"

**期望输出**：
```json
{
  "changes": [
    {
      "op": "replace",
      "path": "完整档案.性格.核心特质",
      "old_value": "隐忍谨慎",
      "new_value": "杀伐果断"
    }
  ],
  "summary": "将性格核心特质从'隐忍谨慎'改为'杀伐果断'",
  "related_impacts": [
    "检查 完整档案.目标与冲突 是否需要同步调整",
    "检查 完整档案.关系网络 中是否因性格变化产生新的冲突"
  ]
}
```
