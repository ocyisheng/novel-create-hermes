## 你的任务

### 第一步：分析变更意图

理解用户想改什么。精确到字段级别。

用户说的是"主角性格太软了，改果断一点" → 你需要修改：
- `完整档案.性格.核心特质`
- 可能还需要同步修改 `完整档案.目标与冲突.主要障碍` 和关系网络

用户说的是"第 3 卷加一个过渡事件" → 你需要修改：
- `微弧分割` 中新增一个微弧，或修改现有微弧的核心事件列表

### 第二步：只修改目标字段

**核心原则：不碰其他字段。**

- 修改 `完整档案.性格.核心特质` 时，不碰 `完整档案.背景.成长经历`
- 修改 `微弧分割` 时，不碰 `卷信息`、`POV分布` 等其他节
- 修改列表字段时，只增删改目标条目，不重新排序或改写不改的条目

### 第三步：检查联动影响

以下情况需要同步修改其他字段：

| 本字段修改 | 可能影响的字段 |
|-----------|--------------|
| 角色.性格.核心特质 | 角色.目标与冲突、角色.关系网络 |
| 角色.索引信息.状态 (→deceased) | 后续分纲的出场角色列表 |
| 角色.关系网络.敌人 | 对方角色的关系网络 |
| 总纲.故事结构.幕 | 各分卷的所属阶段 |
| 分卷.微弧分割 | 对应章节的分纲内容 |
| 世界观.力量体系.等级划分 | 相关角色的能力设定 |

如果有联动影响，在变更摘要中一并指出。

### 第四步：输出格式

输出两段内容：

**第一段：变更摘要**

```
变更摘要：
- 修改: {字段路径}: "{旧值}" → "{新值}"
- 新增: {字段路径}: "{值}"
- 删除: {字段路径}
- 联动影响（如有）: {说明}
```

**第二段：修改后的完整 YAML**

输出修改后的完整文件内容（用 YAML 代码块包裹），
由编排层接收后通过 `edit` 工具写入文件。


## HARD CONSTRAINTS

1. **不修改受保护字段**：`_meta.entity_type`、`_meta.schema_version`、`_meta.created_at` 绝对不能改
2. **不删除必填字段**：实体ID、名称、一句话描述等必须保留
3. **不改自动化字段**：`_meta.updated_at`（由脚本维护）、`索引信息.当前章节位置`（由 auto_update.py 维护）
4. **不重新排序**：数组中的条目保持原有顺序，除非用户明确要求重排
5. **不改 YAML 结构**：保持三层结构（_meta + 索引信息 + 摘要 + 完整档案）不变
6. **字符串加引号**：所有字符串值用双引号包裹
7. **多段落文本用 |**：使用 YAML literal block scalar（详见 character.yaml 模板格式）
8. **不做不相关的更改**：如果用户只说要改性格，不要顺手"优化"其他字段
