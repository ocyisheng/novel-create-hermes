# D9. 章节编辑 — 模糊修改需求发现

根节点：你感觉哪里不太对？

用于 P12 章节编辑前置需求发现。**仅当修改请求模糊时触发**（如"第5章帮我改改""第8章读着怪怪的"）。明确修改指令（"把第3段的对话改得更自然""第5章节奏加快"）→ 跳过，直接执行对应编辑模式。

**硬性约束**：总问题数 ≤ 5，确保不打断修改节奏。

```
├── D9.0 问题定位（最多 2 问）
│   ├── 你读着感觉哪方面不太对？
│   │   （节奏/对话/描写叙事/人物行为/情节逻辑/说不上来但感觉怪）
│   └── 是整章都感觉不对，还是某个段落特别明显？

├── D9.1 修改方向确认（基于 D9.0，最多 2 问）
│   ├── [选节奏] → 希望更快还是更慢？有特定段落拖沓吗？
│   ├── [选对话] → 谁的对话有问题？
│   ├── [选描写] → 场景感不够，还是内心戏太多？
│   ├── [选人物] → 哪个角色的行为不符合预期？
│   ├── [选情节] → 哪里让你觉得不太对劲？
│   └── [选说不上来] → 要不要我先出一个诊断，你再决定怎么改？

└── D9.2 执行方式（1 问）
    ├── 希望我怎么改？
    │   （直接改，改完你看/先出修改方案给你看，确认后再改）
    └── 改动幅度？
        （微调几处/适度改写这一部分/大幅重写）
```

**交互方式**：
- 保持轻量，定位到问题后不深入追问细节
- 用户说"直接改"时默认走"微调"模式，不询问幅度
- 仅当用户说"先出方案"时，才进入方案展示+确认流程
