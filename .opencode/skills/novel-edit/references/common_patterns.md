# 常见编辑模式

按编辑对象分为三类：YAML 实体编辑、TXT 章节编辑、跨文件联动编辑。

## YAML 实体编辑

### 模式 A：字段值替换

最常见的操作。用户说"把性格改成更冷酷"。

```json
{
  "changes": [
    {
      "op": "replace",
      "path": "完整档案.性格.核心特质",
      "old_value": "隐忍谨慎",
      "new_value": "冷酷果断"
    }
  ],
  "summary": "核心特质从 '隐忍谨慎' 改为 '冷酷果断'",
  "related_impacts": ["检查 目标与冲突 是否需要同步更新"]
}
```

**注意**：如果 `old_value` 不确定（用户没给原文），先 read 确定再构造变更集。

### 模式 B：新增字段

用户说"给主角加一个隐藏身份"。

```json
{
  "changes": [
    {
      "op": "add",
      "path": "完整档案.隐藏身份",
      "value": "组织代号「幽灵」，外表是普通书店老板"
    }
  ]
}
```

**注意**：确认该字段在原 YAML 中不存在，否则用 `replace`。

### 模式 C：列表操作

用户说"追加一个新的弱点"或"删掉第三个势力关系"。

```json
{
  "changes": [
    {
      "op": "add_to_list",
      "path": "完整档案.弱点",
      "value": "无法拒绝他人的求助",
      "position": "末尾"
    }
  ]
}
```

```json
{
  "changes": [
    {
      "op": "remove_from_list",
      "path": "完整档案.势力关系",
      "index": 2
    }
  ]
}
```

**注意**：列表索引从 0 开始。删除前 read 确认目标位置。

## TXT 章节编辑

### 模式 D：段落级精确替换

用户说"把第三章开头那段对话改一下"。

```
① read 章节文件定位目标段落
② edit 工具精确替换目标文本
③ 只改用户指定的段落，不碰其他内容
```

**禁忌**：不要为了改一段话而重写整章。

### 模式 E：通篇润色

用户说"润色第五章"或"帮忙修一下这章的节奏"。

```
① read 整章 + 对应分纲 + 活跃风格（如有）
② 整体节奏：检查段长分布，过长段落拆分，过短段落合并
③ 用 edit 工具逐段修改（不要一次 write 覆盖全文）
④ 改完后 read 检查衔接
```

**注意**：保留原文的核心情节走向和角色对话声音，不改变故事内容。

### 模式 F：扩写/缩写

用户说"这段打斗写得太简单了，展开一下"或"这段心理描写太啰嗦了，精简一点"。

- **扩写**：增加细节（环境/动作/感官/心理），不改变叙事方向
- **缩写**：合并句子，删除冗余修饰，保留核心信息
- 两种操作都保持在分纲规定的场景范围内，不新增或删除情节节点

## 跨文件联动编辑

### 模式 G：角色重新命名

用户说"把主角的名字从'李明'改成'林枫'"。

```
① YAML：变更集 replace 角色文件中的名称字段
② 索引：写后处理自动 rebuild_project_index.py 处理
③ 章节：搜索 chapters/ 所有 .txt 中旧名 → 用 edit 逐个替换
④ 关联：搜索其他角色/世界观的 YAML 中是否有旧名引用
```

**不要手动修改 `project_index.yaml`**——后处理脚本会自动重建。

### 模式 H：回退到上一次编辑

用户确认方向后说"不对，恢复之前的版本"。

```
① 定位 .bak 文件（apply_changes.py 自动创建）
② 删除当前文件，将 .bak 重命名恢复
③ 运行 rebuild_project_index.py 更新索引
④ 调用 update_intent_log.py --status rejected
```
