```yaml
创意质量评估报告:
  评估时间: 2026-05-05 10:00
  创意总数: 6
  通过筛选: 3

  通过的创意:

    创意B (ID: creative_002):
      评分: 原创性:5/5, 可行性:3/5, 吸引力:4/5, 独特性:4/5

  拒绝的创意:
    创意D (ID: creative_004): 总分13, 原创性不足
```

## 处理流程

### 输入
```yaml
评估输入:
  创意列表:
    - 一句话概述: "..."
      核心概念: "..."
      基本设定: "..."
  评估模式: "严格模式/标准模式/宽松模式"
  作品类型: "玄幻/都市/科幻等"
```

### 阶段一：数据收集
```
输入：待评估创意列表
  ↓
收集每个创意的完整信息
  ↓
确认一句话概述、核心概念、基本设定
  ↓
输出：创意数据包
```

### 阶段二：维度评分
```
输入：创意数据包
  ↓
对每个创意的4个维度分别打分：
├── 原创性 (0-5分): 概念的新颖程度
├── 可行性 (0-5分): 概念的可执行度
├── 吸引力 (0-5分): 对目标读者的吸引程度
└── 独特性 (0-5分): 在市场上的差异化程度
  ↓
输出：评分数据
```

### 阶段三：阈值筛选
```
输入：评分数据 + 评估模式
  ↓
应用筛选标准：
├── 总分 ≥16/20 (标准模式)
├── 原创性 ≥4分 (避免套路化)
├── 吸引力 ≥4分 (确保有读者吸引力)
└── 其他维度 ≥2分
  ↓
输出：通过/拒绝创意列表
```

### 阶段四：优先排序
```
输入：通过筛选的创意
  ↓
按总分降序排列
  ↓
输出：排序后的创意列表
```

### 阶段五：改进建议
```
输入：未通过/评分较低的创意
  ↓
对每个低分维度提供具体改进建议
  ↓
输出：改进建议报告
```

## 单创意详细评估示例

```yaml
创意深度评估报告:
  创意ID: creative_001
  创意概述: "在末法时代用科学方法重新解读并再造修仙体系"

  维度评分详情:
    原创性: 4/5
      分析: "科学修仙概念有创新，但近年有类似作品"
      改进: "可增加更独特的科学解释角度"

    可行性: 4/5
      分析: "科学方法可执行，但需要考虑科学严谨性"
      改进: "建立更严谨的科学-修仙对应关系"

    吸引力: 5/5
      分析: "融合科学与玄学，对两类读者都有吸引力"
      优势: "同时吸引科幻和玄幻读者群"

    独特性: 4/5
      分析: "在科学修仙领域有自身特色"
      改进: "增加独有的科学修炼体系"

  总体评估: "总分17/20，优秀创意，建议优先选择"
  开发优先级: 高
  风险评估: "中低（需要保持科学严谨性）"
```

## 创意对比评估示例

```yaml
创意对比评估报告:
  对比创意: "A vs B vs C"

  对比维度:
    原创性: "A(4) < B(5) > C(4)"
    可行性: "A(4) > B(3) > C(4)"
    吸引力: "A(5) > B(4) < C(4)"
    独特性: "A(4) = B(4) > C(3)"
    总分: "A(17) > C(15) > B(16)"

  优势分析:
    - "创意A: 综合最优，吸引力突出且可行性高"
    - "创意B: 原创性最强但实现有挑战"
    - "创意C: 平衡但缺乏突出亮点"

  建议推荐:
    主选: "创意A (综合最优)"
    备选: "创意B (原创性突出，可优化实现路径)"
    待考虑: "创意C (需要提升独特性)"
```
