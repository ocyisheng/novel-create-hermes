# 创作需求发现与压力测试技能

## 核心职责

两种模式：

- **预生成模式**（默认）：在 task() 生成内容前，主动追问用户需求偏好，将确认后的信息作为生成输入。流程：**追问→确认→生成**。
- **事后评估模式**：用户对已有产出（创意/大纲/角色/章节）说"grill 一下"，读文件逐层追问评估。

## 上下文契约

编排层在调用本技能前按以下清单加载上下文：

| 槽位 | 来源 | 说明 |
|------|------|------|
| `{项目名}` | config.yaml | 当前项目名称 |
| `{模式}` | 编排层指定 | `discovery`（预生成）/ `evaluation`（事后评估） |
| `{测试阶段}` | 编排层指定 | `ideation` / `outline` / `character` / `chapter` |
| `{测试对象概要}` | 对应阶段 | 预生成时：描述要生成什么；事后评估时：已有内容摘要 |
| `{测试对象路径}` | 对应阶段输出文件 | 预生成时：空；事后评估时：已有文件路径 |

## 决策树引用

> 决策树定义已拆分为独立参考文件，避免占用 SKILL.md 篇幅。执行时按模式先读取对应文件再逐层追问。

| 模式 | 文件 | 说明 |
|------|------|------|
| 预生成 | `references/discovery_trees.md` | D1-D4 需求发现树（你想要什么） |
| 事后评估 | `references/evaluation_trees.md` | 1-4 评价检查树（这个做得怎么样） |

## 工作流程

### 预生成模式（`{模式}=discovery`）

**目标**：在 task() 生成前收集用户需求，输出结构化需求文档供编排层注入生成 prompt。

1. **读决策树**：`read references/discovery_trees.md`，根据 `{测试阶段}` 选择对应 D 树
2. **逐层追问**：向用户解释"在开始之前，我先问几个问题了解你的想法"，每问附推荐答案，用户可 `pass` 跳过分支
3. **整理需求**：将确认信息整理为清单（分支结论、关键需求、排除方向）
4. **输出文件**：按 `assets/discovery_report.yaml` 模板写入 `quality/grill/{测试阶段}_需求_{时间戳}.yaml`，编排层读取后注入 task() CONTEXT

**追问风格**：逐个提问，每问附推荐答案（基于类型常识和项目已有背景），用户确认或修正后记录结论再进下一问题，走完所有分支为止。

### 事后评估模式（`{模式}=evaluation`）

**目标**：对已有产出进行压力测试，发现薄弱环节。

1. **读对象**：读取 `{测试对象路径}` 文件，加载完整内容及辅助材料
2. **读决策树**：`read references/evaluation_trees.md`，根据 `{测试阶段}` 选择对应评价树
3. **逐层追问**：从根节点出发，每问附推荐答案（基于已读内容分析），用户 `pass` 跳过，`stop` 终止
4. **输出报告**：按 `assets/evaluation_report.yaml` 模板写入 `quality/grill/{测试阶段}_评估_{时间戳}.yaml`，展示摘要，等待用户决策（接受 / 修改后重来）

## HARD CONSTRAINTS

1. **不替代创作决策** — 只揭示问题、提供分析，最终选择权在用户
2. **每个问题必须有据** — 基于已读内容或类型常识，不凭空提问
3. **推荐答案必须具体** — 有依据的分析，不泛泛而谈
4. **尊重用户中断** — `pass` 跳过当前分支，`stop` 立即终止，不追问原因
5. **输出后等待决策** — 输出报告后，给出"接受 / 修改后重来"选项，等待用户选择
